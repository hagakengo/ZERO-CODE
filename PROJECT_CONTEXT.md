## 4. Protagonist

The protagonist is anonymous.

### Visual identity

- adult male-presenting silhouette
- slim-to-average build
- black oversized hoodie
- black / charcoal cargo pants
- black sneakers
- angular black tech backpack
- mostly back view or 3/4 rear view
- face never clearly visible
- no weapons
- no unnecessary accessories

### Absolute lighting rule

> THE PROTAGONIST DOES NOT GLOW.  
> ONLY ZERO CODE GLOWS.

No fluorescent hoodie lines.

No cyan trim on clothing.

No glowing seams.

Dimensionality comes from material differences:

- hoodie: matte black
- pants: charcoal / slightly gray-black
- backpack: harder technical charcoal
- hardware: gunmetal

- backpack is blank
- no ZERO CODE emblem

During activation:

- system detects ZERO CODE

## 6. ZERO CODE emblem

Current chosen design direction:

**D1**

Current asset status:

**D1 v1.1 — Production Master Candidate**

It is NOT yet final `D1 MASTER v1.0`.

### Why D1

D1 was preferred over more polished directions because it feels:

- incomplete
- broken
- asymmetric
- mysterious
- reconstructed
- less corporate
- more story-driven

Key concept:

> 欠けていることが、完成形である。

Another production principle:

> 複雑さではなく、不完全さで個性を出す。

### Critical D1 anchors

1. **BROKEN ZERO** — incomplete asymmetric outer zero/ring.
2. **A AXIS** — rising diagonal/angular A-like main axis.
3. **CENTRAL CORE** — cyan glowing core.
4. **LOWER-RIGHT FRACTURE** — distinctive broken/missing lower-right structure.
5. **INTERRUPTED PATH** — incomplete orbit/path.

### Never do this to D1

- complete the circle
- symmetrize it
- polish away the fractures
- redesign it shot-by-shot
- rotate it randomly
- change proportions
- relocate the core
- change the primary glow away from cyan
- add decorative micro-lines that harm reproducibility

### Production instruction

> DO NOT REDESIGN D1.  
> FILM IT.

Treat it as a manufactured physical object that already exists.

## 11. Repository philosophy

Manage ZERO CODE like a software project.

- Visual Bible = design specification
- RULES = coding conventions / hard constraints
- Character Sheet = type definition
- MASTER assets = canonical source assets
- Episode = implementation
- 作画崩壊 = bug
- Setting change = version update
- Production Log = decision history
- Git = historical record

Never erase useful failure history.

Archive:

- rejected emblem concepts
- over-clean revisions
- failed generations
- mutated ¥0 shots
- old EP.01 prototypes
- rejected prompts
- prompt revisions

These may later become valuable behind-the-scenes content.
