# ZERO CODE STUDIO

## 素材資産管理・再利用規程 v1.0

**規程ID：** ZCS-ASSET-001  
**制定日：** 2026年10月22日  
**制定責任者：** プロデューサー  
**運用責任者：** 監督AI  
**適用対象：** ZERO CODE STUDIOの全制作部門・AI制作担当  
**適用作品：** オリジナルアニメ『ZERO CODE』および関連制作物

---

## 第1条｜基本理念

ZERO CODE STUDIOは、制作した素材を一度限りの消耗品として扱わない。

**「一度作った素材を使い捨てず、磨き、蓄積し、次の作品に生かす。」**

制作資産の蓄積によって、品質・一貫性・制作効率を継続的に高める。

ただし、素材の再利用そのものを目的化せず、作品の品質と物語表現を最優先とする。

## 第2条｜新規制作前の既存素材確認

すべての制作担当は、新規素材を生成する前に既存素材を確認しなければならない。

確認する事項：

1. 同じキャラクター・場所・小道具の素材が存在するか
2. 現行の承認済み設定と整合するか
3. 再利用または修正によって目的を達成できるか
4. 新規生成する場合、その必要性と見込まれるコストは何か

**既存素材の確認を行わず、同等素材を無計画に再生成することを禁止する。**

## 第3条｜素材の分類

すべての素材を以下の状態で管理する。

| 状態 | 意味 |
| --- | --- |
| INVENTORY | 発見・登録済み。内容や権利は未評価 |
| TEST | 技術・演出の検証用 |
| CANDIDATE | 監督レビューを通過した採用候補 |
| MASTER | プロデューサー承認済みの正式素材 |
| ARCHIVE | 旧版・不採用・利用終了などの保管素材 |

ARCHIVEは削除を意味しない。

旧素材や過去のテスト映像を、承認記録なしにMASTERとして扱ってはならない。

## 第4条｜MASTER昇格条件

MASTERへの昇格には、原則として以下を満たす必要がある。

- 承認済み脚本・世界観との整合
- キャラクターや背景の一貫性
- 技術的な品質確認
- 使用権利・公開条件の確認
- 保存先・バージョン・生成履歴の登録
- 監督AIによるレビュー
- プロデューサーによる最終承認

**監督AIやWorkが独断でMASTERに昇格させることは禁止する。**

なお、脚本の正式承認と映像素材のMASTER承認は別々に管理する。

## 第5条｜素材の種類

管理対象には以下を含める。

- キャラクター設定画、表情、衣装
- 背景美術、ロケーション、建造物
- 小道具、紋章、ロゴ
- 絵コンテ、カット基準画像、原画
- 動画、アニメーション、編集データ
- 音声、演技サンプル、効果音、BGM
- 生成プロンプト、モデル設定、制作パラメータ

生成AIの出力だけでなく、人間による編集・修正素材も同じ規程で管理する。

## 第6条｜素材IDとバージョン管理

各素材に一意のIDを付与する。

命名例：

`ZC_EP00_BG_A_001_v01_TEST`

基本情報として以下を記録する。

- 素材ID・名称・種類
- 対象作品・エピソード
- 状態・バージョン
- 制作者・使用ツール・モデル
- 作成日時
- 元素材・参照素材
- 保存先・ファイルハッシュ
- 生成コスト
- 利用条件・権利確認状況
- 使用したカット・エピソード
- レビュー結果・承認者

同じ素材の改良版は新バージョンとして保存し、旧版を上書きしない。

## 第7条｜ZERO CODE OSとGitHubの役割

**ZERO CODE OS：制作資産の管理台帳**

素材の状態、利用先、承認、レビュー、コスト、進捗を管理する。

**GitHub：制作ルールと変更履歴の管理**

規程、設定、プロンプト、指示書、レビュー結果、参照情報、変更履歴を保存する。

動画・音声などの大容量ファイルは適切な素材保管先に保存し、OS・GitHubから参照可能にする。

両者の記録には、対応するOS revisionとGitコミットを残す。

保存が未完了の場合は、完了したと報告してはならない。

## 第8条｜品質優先・コスト管理

素材の再利用は推奨するが、作品の品質を犠牲にしてはならない。

再利用で必要な品質を満たせない場合は、理由を記録して修正または新規制作する。

有料サービスの利用、追加課金、外部公開にはプロデューサーの承認を必要とする。

無料生成であっても、使用クレジットと残高を記録する。

## 第9条｜権利・公開管理

利用規約や商用利用条件が未確認の素材は、内部検証用として扱う。

透かしのある素材、権利条件が不明な素材、第三者の著作物を含む可能性がある素材は、確認が完了するまで公開用MASTERに昇格させない。

権利確認は、素材ごとに利用サービス・プラン・確認日時を記録する。

## 第10条｜既存素材の保全と棚卸し

規程制定以前の素材も管理対象とする。

初回棚卸しでは、以下を優先する。

1. v01〜v03のパイロット映像
2. v04の原画6枚
3. 既存キャラクター・背景・ロゴ案
4. 第0話ティザー用の画像・Klingテスト動画
5. その他の制作済み素材・設定資料

既存素材を自動的にMASTERとせず、最初はINVENTORYまたは現状に適した状態で登録する。

既存の正式承認が確認できる場合は、その記録を引き継ぐ。

## 第11条｜制作ワークフロー

**既存素材確認 → 制作・修正 → TEST → 監督レビュー → CANDIDATE → プロデューサー承認 → MASTER登録 → 次回制作へ再利用**

不採用・旧版となった素材も、必要に応じてARCHIVEとして保持する。

## 第12条｜禁止事項

以下を禁止する。

- 承認済みMASTERの無断上書き・削除
- 既存素材を確認しない無計画な重複生成
- 未承認素材のMASTER扱い
- 生成コストや検証結果の虚偽記録
- 権利未確認素材の無断公開
- 監督・プロデューサーの承認を省略した正史変更
- OSとGitHubの保存状況についての虚偽報告

## 第13条｜既存規程との関係

本規程は、既存のZERO CODE制作ルール、正史管理、MASTER承認権限を変更しない。

既存規程と矛盾する場合は、該当箇所を監督AIが整理し、プロデューサーの判断を受ける。

規程の改訂はバージョン管理し、変更理由と承認記録を残す。

---

## 監督方針

**ZERO CODE STUDIOは、作品を作るたびに資産が増え、品質と制作力が向上するスタジオを目指す。**

素材を大量に作ることではなく、作品に必要な素材を適切に作り、継続して使える状態に育てることを重視する。
