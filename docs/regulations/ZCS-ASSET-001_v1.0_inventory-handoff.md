# ZCS-ASSET-001 v1.0｜運用登録と棚卸し引継ぎ

規程制定の記録と素材のMASTER承認は別の操作。今回の作業は規程の保存と次回棚卸しの登録であり、既存の素材の格上げ・再採番・削除は実施しない。

## 現在の台帳

OS revision 32時点のassetsは68レコード。これは実ファイル68個の確認済みという意味ではない。参照コレクションや別管理素材もあるため、全素材数とも扱わない。68レコードは今回変更しない。

## 次回の開始地点

1. v01〜v03パイロットの原本、保存先、SHA-256、生成履歴・承認根拠を確認する。
2. v04原画6枚を実ファイルと照合する。6枚は規程の指定数であり今回の実測ではない。
3. キャラクター・背景・ロゴ、第0話素材、その他へ順に進む。

## 運用上の注意

- 既存IDと承認記録を保持し、新命名との対応を作る。既存素材を機械的に再採番しない。
- 旧台帳の「候補」「承認済み」をCANDIDATE／MASTERへ自動変換しない。素材ごとの監督レビュー、プロデューサー承認、権利を確認する。
- 記録の作成日時が分からなければ未確認とする。登録日と素材の作成日を混同しない。
- 未取得費用は0円で埋めない。無料生成は消費数・残高・確認時点を残す。
- 同一ハッシュでも用途や承認履歴を削らず、重複候補として確認する。
- 第1話のC案採用など脚本の承認を、画像・映像のMASTER承認へ流用しない。
- 第0話Klingの原動画と縦型A/B/CはTESTのまま。制作側推薦Cを監督合格と扱わない。追加生成・課金・公開を行わない。

規程の権限・承認方針と既存制作ルールに、この登録で解決を要する直接の矛盾は見つからない。旧状態名と新分類の対応、旧IDと新命名の対応は棚卸し時に個別検討する。保存領域は既存STORAGE_GUIDEを継続使用する。
