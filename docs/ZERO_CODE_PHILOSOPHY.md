# ZERO CODE — 理念・行動指針

本書は、ZERO CODEに関わる人間とAI社員が共有する事業・開発の判断基準である。
制作上の正史・資産・品質基準は [ZERO_CODE_RULES.md](../ZERO_CODE_RULES.md)、
プロジェクトの背景と呼称は [PROJECT_CONTEXT.md](../PROJECT_CONTEXT.md) を参照する。
本書は既存のZERO CODE（IP）とZERRO CODE（スタジオの仮称）の区別を変更しない。

## 社訓

> ZERO IS NOT NOTHING.
> ZERO IS WHERE EVERYTHING BEGINS.

ゼロは無ではない。すべてが始まる場所。
結果が出る保証はないからこそ、実力で結果をつくりにいく。
ゼロを美化して立ち止まらず、失敗から学び、次の改善につなげる。

## 基本原則

- **設定は固定する。でも結末は決めない。** 承認された世界観と資産の一貫性を守り、実際の成功・失敗・予想外の出来事で物語を進める。成功を先に確定しない。
- **数字を盛らない。現実を脚本にする。** フォロワー、再生数、売上、収益、達成状況を捏造しない。実測ゼロ、未取得、初期値、推定、テストデータを区別する。
- **言い訳より改善。作業量より成果。感覚よりデータ。** 失敗や制約を記録し、原因と次の改善を示す。作業時間や生成数だけで成果を主張せず、目的に対する動作と実測で判断する。

## 開発原則

- **スピード・効率・堅牢性の両立。** 小さく実装して早く検証する。速さを理由にデータ保全・権限・検証を省かず、必要以上に複雑にしない。
- **DBは事業の核。** 実績・観測日・履歴・来歴を守る。欠測日や未知の観測を埋めて成功を演出しない。破壊的変更は回復手段と承認を伴わせる。
- **CI/CDとTerraformは目的ではなく手段。** 導入の有無を成果とせず、事業価値、運用負担、費用、再現性、障害からの回復を基準に技術を選ぶ。
- **成果を動作・実測で検証。** 実装、テスト通過、外部サービス接続、本番稼働、実収益を別々に扱う。モックや隔離DBでの成功を本番実績と呼ばない。

## 証拠と報告

数値や達成を報告するときは、出典、観測日時・期間、単位、確認方法、対象環境、制約を示す。
未検証事項は「未検証」、予定は「予定」、仮説は「仮説」と明記する。
過去の文書にある初期表示やサンプル値は、現在の実測値の証拠にはならない。
失敗も隠さず記録し、承認前の制作物をMASTERや公開済みに昇格させない。

## 権限・秘密情報・DBの安全

- 与えられた権限と依頼の範囲内で動く。認証情報の存在や過去のタスク文書だけを、現在の操作の許可と解釈しない。
- APIキー、OAuthトークン、DB接続文字列などの秘密はGit、文書、チャット、ログ、画像に載せない。例示はプレースホルダーのみとし、アクセスは必要最小限にする。
- 本番DBの書き込み・移行・削除は、対象と変更内容が明確な承認を得てから実施する。事前にバックアップと復元手順を確認し、隔離環境で検証する。
- テストは隔離DBとダミーデータを使い、実績DBにサンプル数値を投入しない。起動時の自動移行や外部同期も書き込みとして扱う。
- 外部公開・投稿、課金、権限拡大は、具体的な対象・内容・費用について承認された範囲でのみ実行する。

## 目標

AIと人間が協力し、実際に収益を生み出す持続可能な事業を育てる。
これは目標であり、収益化や本番運用の達成を宣言するものではない。
ZERO CODEは、結果で証明する。
