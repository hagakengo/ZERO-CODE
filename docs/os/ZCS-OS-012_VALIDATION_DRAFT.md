# ZCS-OS-012｜隔離実装・検証結果（DRAFT）

実施日：2026-10-23。対象：Studio Memory v0.1を親にした新しい隔離ブランチ。PR #8・#9、本番Reader、既存ZERO CODE OS、MASTER、非公開の既存記憶3件には変更を加えていない。

## 実装

- `backend/app/memory_workflow.py`：完了報告から原文一致の抜粋をDRAFT候補として私有保存。監督・プロデューサーの別々のEd25519公開鍵で審査票を検証。順序・期限・承認範囲・出典ハッシュ・ID重複・保守的な素材重複を確認して新規Markdownを作る。理由付き却下と登録後取消の履歴も保持。
- `backend/tools/memory_workflow.py`：Reader APIとは独立したオフライン管理CLI。候補、署名前審査票、署名適用、登録、状態確認を行う。一般Workの短命Reader資格情報で審査・登録できない。
- `backend/test_memory_workflow.py`：隔離フォルダー、合成報告、テスト専用鍵を使う一連の正常系・異常系。実際の記憶保管庫には書かない。
- [ワークフロー仕様](ZCS-OS-012_WORKFLOW_DRAFT.md)：状態遷移、鍵の分離、出典・差分・監査、運用手順と残課題。

## Work 02連携

Work 02本人に既存の実制作結果報告と演出・作画QCの出典を照会し、ファイルの実在と本文を確認した。Work 01がその報告にある判断と理由を原文一致で選択し、非公開のローカル成果物へ`WORK02-EP00-R03-001`を**DRAFT**として保存した。出典のSHA-256と未承認範囲を保持する。監督・プロデューサー署名はなく、正式記憶保管庫へ登録していない。合成データの別候補では、署名付き承認後の登録と既存Reader APIでの検索・詳細取得を検証した。

Work 02の報告の「技術PASS」はファイルの出力・保全・再現性についての結果であり、演出・作画はREWORKのまま。完成映像・正式原画・MASTER・公開の承認と読み替えていない。

## 監査・差分

管理イベントは対象ID、操作、署名者の役割・申告名、時刻、承認範囲、結果、証明ファイルのハッシュを保存する。本文や認証情報はイベントログに入れない。署名原本はイベントログから分離した私有`proofs/`、新規登録の前後本文は私有`diffs/`に保管する。既存ノートは上書きせず、取り消し時も私有アーカイブと履歴を残す。
