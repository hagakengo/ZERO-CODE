## 1. 現状と前提

リポジトリREADMEには、ローカル **FastAPI + Next.js + SQLite** のZERO CODE OS基盤、ダッシュボード、手動指標更新、YouTube同期機能の記載がある。既存実装の稼働状態・最新OSスキーマ・ローカルデータとの関係は別途実機確認が必要。

制作側のユーザー報告では、OS revision 35にユナ第一原画r02のK05・K07・K08が**表情作画参考候補**として登録されている。GitHubのREADMEはその最新ローカルOSの同期・バックアップ証拠ではないため、実機照合前にデータを上書き・自動移行しない。

EP00ユナ第一原画r03はREWORK。第二原画・本中割り・正式採用・MASTER昇格は未承認。動画が120フレームあることや原画枚数は完成根拠としない。品質基準は「同じユナが自然に演技しているか」。

## 2. MVPの対象

### Phase A：読み取り専用（最優先）
- レスポンシブ画面：制作ダッシュボード、EP00カット一覧、素材一覧、レビュー履歴
- 実際の原画PNGとMP4をサムネイル・全画面・通常速度で閲覧
- r01/r02/r03等のバージョン、出典、SHA-256、制作状態、監督評価、未承認フラグを表示
- K05/K07/K08を「表情作画の参考候補」と明示。完成・MASTERと誤表示しない
- 未取得素材は「未取得」と表示し、無関係な生成画像で代替しない

### Phase B：権限付きレビュー
- 監督：PASS/REWORK/FAIL/UNVERIFIED、タイムコード付きコメント、修正指示の下書き・記録
- プロデューサー：明示的な正式採用・MASTER承認（別操作、二段階確認、監査ログ）
- Work：提出物とQCレポートの取り込み（当初は手動インポート、実装確認後に連携）
- 各操作に actor、時刻、対象バージョン、変更前後、根拠を追記型で記録
- 承認の取り消し・変更も履歴を残し、過去の証拠を消さない

### Phase C：制作・運営拡張（MVP外）
- AI制作チームのジョブ連携、note・X運営、収益ダッシュボード、通知
- 外部APIや自動実行は権限・費用・実行証拠を検証後に別承認

## 3. 技術方針（決定前の提案）

1. 既存Next.jsをフロントエンド、FastAPIをAPIとして再利用できるかコード検証。
2. **現行SQLiteやローカルOSファイルを本番へ直接公開しない。** 最初は隔離されたダミーDBとダミー素材で画面・APIを試作。
3. スマホ/PC対応のレスポンシブWeb。PWA（ホーム画面追加）は段階導入。
4. 本番用には認証・セッション管理・サーバー側認可、HTTPS、非公開オブジェクトストレージ、短寿命の署名付きメディアURL等を設計。プロバイダーは費用・運用条件を比較してから決定。
5. Macの `/Users/...` という絶対パスはスマホから参照できない。素材はハッシュと論理IDで参照し、原本は保持したまま、アクセス制御された配信用コピーを別管理する。
6. 読み取り専用の取り込み→整合性検証→権限付き書き込みの順で段階移行。ID・承認履歴・既存68レコードを勝手に統合・改番しない。
7. 既存OSのrevision番号とGitコミットを混同しない。保存時は双方を別の来歴として記録する。
