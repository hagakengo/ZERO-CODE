# ZCS-OS-011｜Studio Memory安全運用基盤 — 検証報告（DRAFT）

検証日：2026-10-23。対象：Draft PR #9の隔離ブランチ。PR #8・#9、本番ZERO CODE OS、MASTER、非公開記憶ノートは変更していない。

## 接続方式と安全境界

ローカルの読み取り専用FastAPI Readerを127.0.0.1へ限定して起動し、記憶APIだけを既存素材Readerの共通資格情報から分離した。オフライン管理CLIがWorkごとにHMAC署名付きの資格情報を発行する。寿命の上限は15分。APIは発行・失効・更新を受け付けず、検索と詳細取得だけを提供する。秘密ディレクトリと資格情報ファイルはGitの外に置く。

| Work | 最大閲覧範囲 | 許可操作 |
| --- | --- | --- |
| Work 01 | APPROVEDのみ | 検索・詳細取得 |
| Work 02 | DRAFTを含む全状態 | 検索・詳細取得 |
| Web BFF | APPROVEDのみ | 検索・詳細取得 |

各資格情報にはWork識別子、承認範囲、操作、発行時刻、期限、個別ID、世代番号が署名される。個別失効はIDを記録し、Work失効はそのWorkの世代番号を上げる。他Workの資格情報はそのまま有効。期限切れの個別失効記録は次の管理更新時に除去する。Web BFFは既存の閲覧セッションと別に専用の短命資格情報を要求する。欠落・期限切れは閉じて失敗する。

## 読み取り監査

監査ファイルはローカルの秘密ディレクトリ内のJSONL。UTC時刻、Work識別子、操作（検索／詳細）、HTTP結果だけを記録する。検索語、記憶ID、本文、URL、IPアドレス、資格情報を記録しない。署名未検証の要求はWork識別子を`unknown`とする。監査ファイルへ記録できなければAPIは503を返す。一般アクセスログがURLの検索語を別途記録し得るため、Reader起動時には`--no-access-log`が必要。

## 残課題

1. Work 01・02が同じmacOSユーザーID上で動く場合、0600ファイルだけでは相互に秘密ファイルを読めない保証にならない。別OSユーザー、専用秘密配布、または独立したリモート認証基盤が必要。
2. ループバックReaderを別ホストからは利用できない。外出先アクセスにはHTTPS、認証基盤、集中監査、共有レート制限、秘密配布、脅威評価が必要。現時点で公開しない。
3. Web BFF資格情報の自動更新はない。期限切れ後は管理者による手動発行・差し替えが必要。
4. 監査ファイルの保存期間・容量上限・ローテーション、端末侵害時の秘密保護は未実装。継続運用前に運用方針を決める。
5. 実機スマホ、外部接続、非公開ノートの正式承認フローは未検証。本文の公開リポジトリへの登録はしない。

## 再接続と失効

具体的なコマンドと承認境界は[Studio Memory v0.1仕様](ZCS-STUDIO-MEMORY-v0.1_DRAFT.md)に記載。資格情報ファイルはWorkごとに新規作成し、チャット・ログ・GitHubへ内容を貼らない。接続時は記憶IDと承認範囲を必ず読み取り、正式判断として使う前に`approval_status`と`approval_scope`を確認する。接続不能時に共有済みと報告しない。
